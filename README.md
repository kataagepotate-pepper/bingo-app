# ビンゴ大会アプリ（学園祭向け・最大500人同時参加）

学園祭「かまた祭 2026」のビンゴ大会のために作った Web アプリです。
司会がプロジェクターに QR コードを映し、参加者が自分のスマホで読み取ると、その場でビンゴカードが配られます。

- 制作期間：2026年10月（約2週間）
- 担当：要件決め・設計・実装・テスト・公開・本番運用まで一人で担当
- 開発の進め方：AI コーディングツール（Claude Code）を使って開発しました。何を作るか、どういう仕組みにするか（下の「工夫したところ」）は自分で決め、AI にはコードを書く作業を手伝ってもらっています

## できること

| 画面 | 使う人 | 内容 |
|---|---|---|
| 映写画面 `/screen/大会コード` | 会場のプロジェクター | 引いた番号・これまでの番号・ビンゴした人を大きく表示。始まる前は参加用の QR コードを表示 |
| 司会リモコン `/host/大会コード` | 司会（スマホ） | 「番号を引く」「QR コードを見せる」の2つのボタンで進行。ドラムロールの効果音つき |
| 参加者画面 `/join/大会コード` | 参加者（スマホ） | 自分のカードを表示し、出た番号に自動で穴をあける。ビンゴしたら申告 |

当選者が20人に達すると大会は自動で終わります。

## 使った技術

- フロントエンド：React 19 / Vite
- サーバー：Netlify Functions（Node.js）
- データベース：Supabase（PostgreSQL）。パソコンの中で試すときは PGlite（ブラウザや Node.js で動く PostgreSQL）
- テスト：Node.js 標準のテストランナー（`node --test`）

## 工夫したところ

### 1. 500人が同時に使っても落ちないようにした
参加者のスマホは、数秒ごとにサーバーへ「今どうなってる？」と問い合わせます（ポーリング）。500人がそのままデータベースに届くと負荷が大きすぎるので、

- **大会の状態を CDN に1秒だけキャッシュ**：何百人が問い合わせても、データベースまで届くのは1秒に1回程度で済む
- **データベースはプール接続（Transaction pooler）**：サーバーの関数がたくさん同時に動いても、接続数があふれない
- **リアルタイム通信（WebSocket）は使わずポーリングに**：Supabase の無料プランでは同時接続数の上限が足りなかったため

500人がいっせいに参加して状態を取りに来る状況を再現する負荷テスト（`scripts/loadtest.mjs`）を作り、問題なく動くことを確認しました。

### 2. 無料プランの中で収まるように、通信の量を計算して決めた
Netlify の無料プランは月に使える量（クレジット）に上限があり、超えても追加購入できません。
「1時間の大会で何クレジット使うか」を見積もり、参加者の更新間隔を決めました（500人なら5秒ごと → 当日の参加者が約50人に減ったため1秒ごとに変更）。

### 3. 当選者を「ちょうど20人」にする
ビンゴ申告が同じ瞬間に何十人も届いても、当選者が20人を超えないように、

- 当選者の記録はデータベースの **トランザクション** の中で人数を数えてから追加
- 同じカードが二重に当選しないよう **一意制約**（大会 × カードで1件だけ）

テストで「30人が同時に申告しても当選はちょうど20人」になることを確かめています。

### 4. ずる・いたずら対策
- カードの本人確認用の合言葉と、司会の合言葉は **ハッシュ化** して保存（データベースが漏れても元の値が分からない）
- 同じ回線から大会を作りすぎると止める（1時間20回まで）、7日たった大会は自動で削除
- 名前に入った見えない文字や、文字の向きを変える記号は取り除く
- セキュリティ用のヘッダー（Content-Security-Policy など）で、外部のスクリプトを読み込めないようにした

### 5. 会場にネットがなくても使えるオフライン版
「会場に Wi-Fi がなく、参加者がスマホを使えないかもしれない」と分かった時点で、紙のカードと組み合わせて使う **オフライン版**（ネット不要の HTML ファイル1つ）も作りました（`offline/`、`npm run offline` で作成）。

## 本番で起きたトラブルと対応
本番前に、データベースに接続できず「password authentication failed」で止まったことがありました。
Netlify のログから原因（データベースのパスワード変更が Netlify 側の設定に反映されていなかった）を特定し、接続設定を入れ直して再公開して復旧しました。

## パソコンで動かす

```sh
npm install
npm start        # http://localhost:8787 で起動（データベースは PGlite を使うので準備不要）
npm test         # テスト（10件）
npm run loadtest # 負荷テスト（別のターミナルで npm start を動かしておく）
```

本番（Netlify + Supabase）では、Supabase の SQL Editor で `db/schema.sql` を実行し、Netlify の環境変数 `DATABASE_URL` に接続文字列を設定します。

## このリポジトリに含めていないもの
- かまた祭の公式素材（ロゴ・キャラクター・イラスト）：学校・実行委員会の著作物のため
- 効果音（[効果音ラボ](https://soundeffect-lab.info/) の音源）：音声ファイルそのものの再配布が禁止されているため

そのため、このリポジトリだけで動かすと画像と音は出ません。
